# Обход домов — Android-приложение

Автономное приложение для регистрации, учёта и контроля результатов обхода жилых домов,
подъездов и квартир. Реализовано по ТЗ v3.0: Kotlin + Jetpack Compose + Material 3 + Room (MVVM),
работает полностью офлайн, все данные — локально на устройстве.

## Возможности

- Участки, подъезды, этажи и квартиры с автоматической нумерацией снизу вверх.
- Мастер создания участка (2 этапа): название → настройка подъездов (этажи, начальный номер,
  квартиры на каждом этаже). Проверки: обязательное название, уникальность подъездов,
  отсутствие пересечений номеров квартир, транзакционное создание (п. 4 ТЗ).
- Схема подъезда: последний этаж вверху, номер этажа слева, плитки квартир с цветовой
  индикацией статусов, вертикальная и горизонтальная прокрутка.
- Статусы квартир: Отказ (красный), Нет дома (жёлтый), Повтор (зелёный), Не жилая (серый),
  сброс статуса; заметка (телефон + комментарий) с иконкой «i».
- Информационное окно: статус, дата последнего обхода, телефон с кнопкой вызова через
  `ACTION_DIAL` (без автоматического звонка), комментарий.
- История посещений: только добавление (без перезаписи), события «Посещение» / «Сброс» /
  «Исправление», отображение от новых к старым.
- Фильтрация: Все / Повтор / Без обхода / Отказ / Нет дома / Не жилая + кнопка сброса.
- Перемещение квартиры между этажами: долгое нажатие → выбор этажа или drag-and-drop,
  с подтверждением (можно отменить). Номер, статус, телефон, комментарий и история сохраняются.
- Логическое удаление квартир + раздел «Удалённые квартиры» с восстановлением.
- Статистика по участкам/подъездам: обработано по факту посещений из истории.
- Редактирование подъездов: номер, добавление/удаление этажей (п. 19).
- Экспорт XLSX (3 листа: Квартиры, История, Сводка; автоширина, закреплённая строка,
  автофильтры) и CSV (UTF-8 с BOM, разделитель «;», экранирование) через SAF.
- Резервное копирование: ZIP с `backup.json`, проверка версии и целостности,
  восстановление в одной транзакции, перенос на другое устройство.

## Структура проекта

```
app/src/main/java/ru/obkhod/app/
├── MainActivity.kt            # Activity + возврат к последнему экрану (п. 21)

├── data/repo/                 # AreaRepository, EntranceRepository, Models.kt
├── export/                    # ExcelExporter, CsvExporter, ExportDataLoader
├── backup/                    # BackupManager (ZIP + JSON, транзакционное восстановление)
└── ui/
    ├── theme/                 # Material 3 светлая/тёмная тема
    ├── areas/                 # Главный экран — список участков
    ├── create/                # Мастер создания участка
    ├── area/                  # Экран участка — плитки подъездов
    ├── entrance/              # Схема этажей — основной экран
    ├── apartment/             # Инфо-окно и история посещений
    ├── deleted/               # Удалённые квартиры
    ├── edit/                  # Добавление/редактирование подъезда
    └── settings/              # Экспорт, бэкап, очистка данных (п. 20)
```

## Сборка

Требования: Android Studio (Koala или новее) или Gradle 8.14+, JDK 17, Android SDK 35.

```bash
# Windows (в Android Studio достаточно открыть проект и нажать Run)
gradlew assembleDebug      # отладочный APK: app/build/outputs/apk/debug/app-debug.apk
gradlew assembleRelease    # release-сборка: app/build/outputs/apk/release/app-release.apk
gradlew testDebugUnitTest  # модульные тесты
```

Release-сборка подписана debug-ключом для возможности немедленной установки
(для публикации замените на собственный ключ в `app/build.gradle.kts`).

## Установка APK

1. Скопируйте `app-release.apk` на смартфон.
2. Откройте файл и разрешите установку из неизвестных источников.
3. Требуется Android 8.0 (API 26) или новее.

## Принятые проектные решения (по п. 26 ТЗ)

| Вопрос | Решение |
|---|---|
| Удаление участка | Каскадное (подъезды, этажи, квартиры, история удаляются вместе) |
| Удаление квартиры | Логическое (`deleted_at`); данные и история сохраняются; восстановление из раздела «Удалённые» |
| «Без обхода» | Отличается от «сброшенного статуса» по наличию записей в `visit_history` |
| Дата последнего обхода | Не меняется при заметках, перемещении и просмотре; сохраняется при сбросе статуса |
| Перемещение квартир | Только внутри подъезда; дубликат номера на этаже запрещён; подтверждение перед выполнением |
| Удаление этажа с квартирами | Квартиры логически удаляются после подтверждения (история сохраняется) |
| Восстановление копии | Валидация → замена всех данных одной транзакцией; при ошибке данные не меняются |
| Релиз-подпись | Debug-ключ для локальной установки; для Google Play нужен собственный ключ |

## Репозиторий и обновления

Репозиторий: https://github.com/mkisten/moy-uchastok

Приложение при запуске проверяет последний GitHub Release и, если его версия выше
установленной, предлагает обновиться (с описанием изменений и кнопкой «Обновить»,
открывающей скачивание APK). Без интернета проверка просто пропускается.

### Процесс выпуска новой версии

1. Поднять версию в `app/build.gradle.kts`:
   - `versionCode` — увеличить на 1 (целое, для логики обновления);
   - `versionName` — например «1.1.0» (для отображения).
2. Собрать release: `gradlew assembleRelease`.
3. Закоммитить и запушить.
4. Создать релиз с APK:
   ```bash
   gh release create v1.1.0 "app/build/outputs/apk/release/app-release.apk#МойУчасток-v1.1.0.apk" \
     --title "Мой участок 1.1.0" --notes "Что нового..."
   ```
   Тег должен начинаться с `v` и совпадать с versionName.
   ВАЖНО: имя APK должно содержать номер версии (`#МойУчасток-v1.1.0.apk`), иначе все
   обновления сохраняются на телефоне под одним именем `app-release.apk` и легко
   установить старый файл из «Загрузок».
5. Установившие старую версию при следующем запуске получат предложение обновиться
   (скачанный APK открывается как обновление поверх старой версии, данные сохраняются).

## Синхронизация команды через Google Apps Script

Данные команды ведутся в закрытой Google Таблице владельца. Участникам нужны ссылка
на веб-приложение и одноразовый код. Права на таблицу, Google OAuth Client ID и
пересборка APK для каждой команды не нужны.

### Настройка владельцем

1. Создайте новую закрытую Google Таблицу. Откройте **Расширения → Apps Script** и
   вставьте содержимое [Code.gs](server/team-sync/Code.gs) вместо шаблона.
2. Сохраните проект. Запустите `setupTeam` в редакторе и подтвердите доступ к таблице.
3. Создайте развёртывание типа **Веб-приложение**, выполнение **от моего имени**,
   доступ **Все / Anyone**. Скопируйте ссылку **/exec**. Ссылка доступна для запросов,
   но для чтения и записи требуется ключ зарегистрированного устройства. Таблицу
   оставьте закрытой. Если политика Google Workspace не разрешает такой доступ,
   для этого варианта понадобится аккаунт, где он доступен.
4. Запустите `createOwnerInvite` и возьмите код из журнала выполнения. На телефоне
   с исходными данными откройте **Настройки → Синхронизация команды**, введите
   ссылку и код, отметьте **Начать новую команду с данных этого телефона**.
   Начальную загрузку можно выполнить только в пустую команду.
5. Для каждого следующего устройства запустите `createMemberInvite` и передайте
   отдельный код с той же ссылкой. Код действует сутки и привязан к первому
   подключению. Участник подключается с пустой локальной базой. Если на телефоне
   есть свои записи, сначала сделайте ZIP-копию и отдельно решите, какие записи
   нужно перенести в общую базу. Данные прежней интеграции с Google Таблицами
   считываются только с телефона, на котором они уже были синхронизированы.
6. Для отзыва доступа запустите `listDevices`, затем `revokeDevice` с ID нужного
   устройства. Отключение на самом телефоне оставляет его локальную копию.

На телефонах работает кнопка **Синхронизировать** и счётчик ожидающих операций.
Обход можно вести офлайн. Разные поля одной квартиры сливаются независимо.
При изменении одного поля на разных телефонах побеждает операция, позже принятая
сервером. Снятие отметки визита, удаление и восстановление передаются отдельно.

Перед подключением отключите Яндекс Диск. Пока команда подключена, полная
замена локальной базы из копии и очистка данных недоступны. Создание ZIP-копии
и экспорт доступны. Лист `_team_operations_v1` служит журналом. Его строки
нельзя редактировать, сортировать или удалять вручную.

Локальные проверки сервера: `node --test server/team-sync/test/Code.test.cjs`.
Стенд `node server/team-sync/test/local-server.cjs` исполняет тот же скрипт с
тестовыми Google-сервисами. Для инструментальной проверки используются две
отдельные базы Room и изолированный APK, разрешающий HTTP только на тестовом
стенде. Развёрнутое веб-приложение нужно отдельно проверить на реальном аккаунте.

## Синхронизация через Яндекс Диск (совместный доступ без настройки)

Настройки → «Синхронизация (Яндекс Диск)» — самый простой способ совместной работы:

1. Создайте «пароль приложения» на https://id.yandex.ru → Безопасность → Пароли приложений
   (тип «Яндекс Диск»). Основной пароль для этого не используется.
2. В приложении: введите логин Яндекса и этот пароль → «Подключить Яндекс Диск».
3. Первый запуск создаёт на диске папку «Мой участок» с файлом данных.
4. Совместный доступ: поделитесь папкой «Мой участок» с участниками штатным шарингом
   Яндекс Диска (по email, роль «Любой по ссылке» не рекомендуется — только конкретные люди).
5. Участники устанавливают приложение, подключают СВОЙ аккаунт Яндекса тем же экраном
   и синхронизируются — данные общие (слияние по UUID: статусы и заметки «последний
   выигрывает», история объединяется, удаление — флаг).

Технически: WebDAV (webdav.yandex.ru) с Basic-авторизацией, файл data.json — снапшот базы
того же формата, что и ZIP-бэкап. Автосинхронизация — при каждом запуске приложения
и по кнопке. Без интернета всё работает локально.
